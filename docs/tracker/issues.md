# Задачи (Issues)

Список задач для GitHub. Каждая задача связана с требованием из [документа требований](../wiki/Requirements.md): 
ID требования стоит в заголовке (`[US-04] …`), так таблица [трассировки](../wiki/Traceability.md) и трекер ссылаются друг на друга.

Создать все задачи сразу: `bash docs/tracker/create-issues.sh OWNER/REPO` (нужен [GitHub CLI](https://cli.github.com/), `gh auth login`).

## Как вести трекер (GitHub Projects)

1. Создайте проект: **Projects → New project → Board**. Колонки: **To Do**, **In Progress**, **Done**.
2. Добавьте все задачи в проект (Add item) — они попадут в To Do.
3. Начиная работу, берёте задачу себе (Assignee), переносите в **In Progress** и создаёте ветку `feature/us-04-create-rule` (формат: `feature|fix|docs|chore/<id>-<кратко>`).
4. Открываете Pull Request: в описании — `Closes #N` и ID требования; после ревью и слияния задача закрывается, карточка уходит в **Done**.
5. В тексте Issue добавьте ссылки на ветку и Pull Request, а номер Issue впишите в таблицу трассировки.

История перемещений по статусам формируется самим GitHub — для этого карточки нужно двигать по мере работы, а не «задним числом».

## Список задач

### [US-01] Рекомендации по REST: GET /recommendation/{user_id}

- **Метка:** `user-story`
- **Требование:** Как Пользователь, я хочу получить по своему идентификатору список рекомендованных продуктов, чтобы узнать, какие предложения банка мне подходят.
- **Критерии приёмки:**
  - Ответ 200 и JSON {user_id, recommendations:[{name,id,text}]}
  - Формат и пути строго по ТЗ
- **Где в коде:** RecommendationController, RecommendationService

### [US-02] Пустой список рекомендаций вместо ошибки

- **Требование:** Как Пользователь, я хочу получить пустой список, если мне пока ничего не подходит, чтобы клиентское приложение работало одинаково во всех случаях.
- **Критерии приёмки:**
  - Ответ 200, recommendations: []
- **Где в коде:** RecommendationService

### [US-03] Фиксированные правила Invest 500, Top Saving, Простой кредит

- **Метка:** `user-story`

- **Критерии приёмки:**

  - Правила объединяются по «И»

- **Где в коде:** Invest500RuleSet, TopSavingRuleSet, SimpleCreditRuleSet, TransactionsRepository

### [US-04] Добавление динамического правила: POST /rule

### [NFR-01] Кеширование запросов к базе клиентов

- **Метка:** `nfr`
- **Требование:** Результаты SQL-запросов кешируются (Caffeine): по одному кешу на метод репозитория, ключ — все параметры запроса.
- **Критерии приёмки:**
  - Повторный запрос рекомендаций не обращается в базу клиентов
  - Не больше трёх методов репозитория и трёх кешей
- **Где в коде:** TransactionsRepository

- **Критерии приёмки:**
